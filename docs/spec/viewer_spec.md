# 뷰어 명세

2026-11-21 보헤님이 승인한 제안의 확정본이다.

## 1. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 3D 방식 | C안: 도면 치수로 직접 모델링하고 스캔 도면을 바닥에 깐다 | 원본이 스캔본이라 벡터와 텍스트를 추출할 수 없다. 바닥 도면이 모델 오차를 눈으로 드러낸다 |
| 조명 | 주목적이 아니다. 손글씨 「조명」 위치 마커만 넣는다 | 보헤님 답변 「아니다」 |
| 진행 순서 | 연구동 3층을 파일럿으로 먼저 만든다. 확인 후 나머지 7개를 만든다 | 외곽이 가장 작다 |
| 검수 | 탭을 만들 때마다 독립 검증 에이전트가 실제 도면과 대조한다 | 보헤님 지시. 작성자가 스스로 승인하지 않는다 |

## 2. 스택

- Vite + TypeScript + React
- three.js + @react-three/fiber + @react-three/drei
- 아이콘은 lucide-react (2026-11-22 추가)
- 상태 관리 라이브러리는 쓰지 않는다. React 상태로 충분하다.
- 실행 중에 PDF를 읽지 않는다. `scripts/prep_plans.py` 로 8장을 기울기 보정 이미지로 1회 변환한다.
- 라이브러리 버전은 설치 시 최신을 받는다. 구현 전에 공식 문서로 API를 확인한다.

## 3. 좌표 규칙

- 단위는 mm다. 장면 단위는 m다(`Viewport.tsx` 의 `M = 0.001`).
- 평면 x는 동쪽(도면 오른쪽), y는 남쪽(도면 아래쪽), z는 바닥에서의 높이다.
- three.js 좌표는 X = x, Z = y, Y = z다.
- 탭마다 원점은 도면 치수선의 시작점이다. `Calibration` 이 300dpi 이미지 픽셀과 mm를 잇는다.

## 4. 값 출처 3종

모든 치수에 출처를 붙인다. 정보 패널이 배지로 표시한다.

| 값 | 코드 | 뜻 |
|---|---|---|
| 도면 표기 | `drawn` | 도면에 숫자로 적힌 치수 |
| 축척 환산 | `scaled` | 도면의 선 위치로 환산한 값 |
| 가정 | `assumed` | 도면에 없어서 가정한 값. 대부분 높이다 |

평면도는 바닥 위치만 준다. 높이는 천장고(CH), 칸막이 높이처럼 도면에 적힌 값만 확정이다.

## 5. 기능

### 1차 범위

1. 탭 8개. 강의동 3개와 연구동 5개를 그룹으로 나눈다. 이름은 도면 우하단 도면명을 따른다. 도면명 끝의 「(변경후)」는 화면에 표시하지 않는다(보헤님 지시, 2026-11-22). 처음 보이는 탭은 첫 탭(강의동 2F 여)이다(보헤님 지시, 2026-11-22. 그 전에는 파일럿인 연구동 3F였다). URL의 `sheet=` 인자로 바꾼다.
2. 3D 모델: 벽, 칸막이, 문(도면에 그려진 열림 상태), 변기, 세면기, 수채기, 거울, 선반.
3. 바닥 도면 깔기와 불투명도 슬라이더.
4. 뷰 전환: 평면(직교) / 아이소 / 눈높이.
5. 절단 높이 슬라이더. 지정 높이 위를 그리지 않는다. 기본값은 그 탭의 천장고(슬라이더의 최대값)다(보헤님 결정, 2026-11-22). 탭을 바꾸면 그 탭의 최대값으로 돌아간다. URL의 `cut=` 인자로 처음 값을 정한다. 눈높이 뷰는 절단하지 않는다.
6. 조명 표시 레이어: 손글씨 「조명」 위치를 천장면 마커로 표시한다.
7. 레이어 켜기/끄기: 벽·창, 칸막이, 문, 위생기구, 거울·선반·부속, 조명 표시, 치수, 바닥 도면.
8. 클릭 정보 패널: 품목명, 도면 주기, 치수와 출처. 판독 메모(`Item.remark`)는 화면에 표시하지 않는다(보헤님 지시, 2026-11-21). 데이터 파일에 기록으로만 둔다.
9. 원본 도면 보기: 해당 페이지 이미지를 2D로 띄운다.
10. 화면 전환 로딩 스피너(보헤님 결정, 2026-11-22): 탭을 바꿀 때, 처음 접속할 때, 실사 ↔ 도면을 바꿀 때 3D 화면 영역에 스피너를 띄운다. 누른 탭의 강조와 스피너를 먼저 그리고, 그 다음에 장면을 바꾼다. 새 장면의 첫 화면이 그려지면 지운다. 도면 모드에서 바닥 도면이 보이는 설정이면 스캔 도면 이미지가 뜬 뒤에 지운다. 30초가 지나면 지운다. 스피너가 떠 있는 동안에는 고품질 렌더를 시작하지 않는다. 스피너가 떠 있는 동안 `.stage` 요소에 `data-loading` 속성이 있다. 검사 도구가 이 속성으로 로딩 끝을 기다린다.
11. 화면의 글자는 명사로 끝낸다(「값이다」 → 「값」. 보헤님 결정, 2026-11-22). 대상은 화면에 보이는 글자와 툴팁이다.
12. 조작법 창(보헤님 결정, 2026-11-22): 처음 접속하면 조작법을 적은 창이 뜬다. 내용은 7절의 표를 줄인 표 한 장과 키보드 한 줄이다.
    - 「다시 보지 않기」를 체크하고 닫으면 다음 접속부터 뜨지 않는다. 체크를 풀고 닫으면 다시 뜬다. 「닫기」, `Esc`, 창 바깥 클릭이 모두 같은 규칙이다.
    - 저장은 `localStorage` 의 키 `toilet-plan-3d-viewer.help.v1`, 값 `'1'` 이다. 공개 주소의 저장소를 다른 프로젝트와 같이 쓰므로 키에 프로젝트 이름을 넣었다. 조작이 바뀌어서 한 번 더 보여 줘야 하면 끝의 판 번호를 올린다.
    - 저장소를 읽거나 쓰지 못하면(사생활 보호 창 등) 매번 뜬다. 화면은 멈추지 않는다.
    - 3D 화면 도구 묶음의 「조작법」 버튼으로 다시 연다.
    - 창이 떠 있는 동안에는 뷰어의 단축키(화살표, `W` `A` `S` `D`, `1`~`8`, `F`)가 듣지 않는다. `Esc` 는 창만 닫는다. 고품질 렌더를 시작하지 않는다.
    - 구현은 브라우저의 `<dialog>` 와 `showModal()` 이다(`src/ui/HelpDialog.tsx`).
    - 검사 도구 `work/tools/cdp.mjs` 는 접속 전에 이 키를 넣어서 창을 끈다. 창 자체를 볼 때는 환경 변수 `CDP_KEEP_HELP=1` 을 준다.

- 조명 위치에 실제 광원을 놓고 밝기 분포 보기

## 6. 화면 배치

```
+------------------------------------------------------------------+
|(강의동 2F 여 3F 남 4F 여) (연구동 1F 2F 3F 여 4F 남 5F 여)       |
+--------------+------------------------------------+--------------+
| 표시 모드    |                                    | 정보         |
| 레이어       |                                    | 품목·치수    |
| 바닥 도면    |            3D 뷰포트               | 도면 주기    |
| 불투명도     |                                    |              |
| 절단 높이    | [평면][아이소][눈높이][맞춤][조작법]| 원본 도면    |
+--------------+------------------------------------+--------------+
|              도면명 · 축척 1/50(A3)            커서 좌표 X,Y (mm)|
+------------------------------------------------------------------+
```

- 탭 줄은 건물마다 탭을 둥근 판 하나에 묶는다. 건물 이름은 판 안의 왼쪽에 있다. 선택된 탭은 강조색 면이다(보헤님 결정, 2026-11-22).
- 좌우 패널의 구획은 카드다. 왼쪽은 표시 모드, 레이어, 바닥 도면 불투명도, 절단 높이다. 오른쪽은 정보, 원본 도면이다.
- 레이어, 상식 보완 품목, 바닥 도면은 눈 아이콘 토글이다. 눈은 보임, 빗금 친 눈은 숨김이다. 줄 전체를 누를 수 있다(보헤님 결정, 2026-11-22).
- 상태 표시줄은 도면명과 축척을 가로 가운데에, 커서 좌표를 오른쪽 끝에 둔다. 조작 안내 글자는 없다. 조작법 창이 대신한다(보헤님 결정, 2026-11-22).
- 원본 도면 카드의 썸네일은 구석에 「⤢ 크게 보기」 판을 항상 보인다. 누르면 원본 도면 창이 열린다. 마우스를 올리면 판과 테두리가 강조색이 되고, 그림이 1.03배로 커지고, 커서가 돋보기가 된다.
- 색과 모양은 10절 「테마」에 있다.

## 7. 마우스와 키보드

| 입력 | 아이소 뷰 | 평면 뷰 | 눈높이 뷰 |
|---|---|---|---|
| 왼쪽 드래그 | 회전 | 이동 | 제자리에서 둘러본다. 좌우 360°, 위아래는 수평에서 60°까지 |
| 오른쪽 드래그 | 이동 | 이동 | 없다 |
| 휠 | 커서 위치 기준 확대·축소 | 같다 | 앞뒤로 걷는다. 한 칸이 250mm다. 확대는 없다 |
| 호버 | 품목 색 강조 + 이름 툴팁 | 같다 | 같다 |
| 클릭 | 품목 선택, 정보 패널에 표시 | 같다 | 같다 |
| 품목 더블클릭 | 그 지점으로 주시점 이동 | 같다 | 그 지점으로 걸어간다. 그 점의 1,000mm 앞에서 멈춘다 |
| 빈 바닥 더블클릭 | 전체 맞춤 | 같다 | 그 점 위에 선다 |

키보드: `1`~`8` 탭 전환, `F` 전체 맞춤(눈높이 뷰는 처음 위치로 돌아간다), `Esc` 선택 해제와 원본 도면 닫기(고품질 렌더 중이면 그 스위치를 끈다), 화살표 키 화면 이동(`Shift` 를 함께 누르면 빠르게 이동한다). `W` `A` `S` `D` 는 화살표 키와 같다(보헤님 지시, 2026-11-22). 글자가 아니라 키 자리로 판정해서 한글 입력 상태에서도 듣는다.

눈높이 뷰의 조작(보헤님 결정, 2026-11-22):

- 눈높이는 그 탭의 `model.eye.from` 높이(1,600)로 고정한다. 드래그, 휠, 화살표, 더블클릭 뒤에도 같다.
- 드래그는 화면을 잡고 끄는 방식이다. 오른쪽으로 끌면 그림이 오른쪽으로 따라온다. 화면 높이만큼 끌면 세로 시야각(45°)만큼 돈다.
- 더블클릭으로 걸어갈 때 높이와 보는 방향은 유지한다. 바닥(높이 약 100mm 이하)을 찍으면 그 점 위에 선다.
- 벽은 막지 않는다. 통과한다.
- 구현: `OrbitControls` 를 그대로 쓴다. 주시점을 카메라의 10mm 앞에 둔다. 확대와 이동을 끄고 극각을 30° ~ 150°로 제한한다. `rotateSpeed` 는 −45 / 360이다. 부호는 화면에서 끌어 보고 정했다.
- 끌고 나서 뗀 것은 클릭으로 치지 않는다(끈 거리가 2px보다 크면 선택을 바꾸지 않는다). 모든 뷰에 같다.

## 9. 실사 모드 (2026-11-21 추가, 연구동 3층 탭에 구현)

보헤님이 파일럿을 본 뒤 추가한 요구다. 연구동 3층 탭에 구현했다. 구현 내용은 9.4절에 있다.

### 9.1 확정된 요구

| 항목 | 결정 | 근거 |
|---|---|---|
| 품질 목표 | 실사. 셰이더를 넣는다. 「top 건축사무소에서 만든 퀄리티 정도」 | 보헤님 지시 |
| 색상 | 호텔 화장실 느낌 | 보헤님 지시 |
| 상식 보완 | 도면에 없어도 상식적으로 있어야 하는 것은 넣는다 | 보헤님 지시 |
| 높이 | 실제 높이 자료는 없다. 상식적인 값으로 정한다. 다시 묻지 않는다 | 보헤님 답변 |
| X 표시 | 물이 빠지는 방향(바닥 구배)이다. 샤프트 표시가 아니다 | 보헤님 답변 |
| 남서 실 배수구 | X 표시 실의 중앙에 배수구를 넣는다 | 작성자 추정을 보헤님이 확인 |
| 위생기구 형상 | 외부 3D 모델을 받지 않고 직접 만든다. 제조사 제품과 똑같지는 않다 | 작성자 추정을 보헤님이 확인 |
| 화면 이동 | 마우스 오른쪽 드래그 이동은 동작한다(보헤님 확인). 키보드 화살표 이동을 추가한다 | 보헤님 요청 |
| 고품질 렌더 | 켜고 끄는 스위치다. 기본은 꺼짐이다 | 보헤님 지시 (2026-11-21. 처음에 켜짐으로 정했다가 화면을 본 뒤 꺼짐으로 바꿨다) |
| 천장 | 실내에서 볼 때만 그린다. 위에서 내려다볼 때는 그리지 않는다 | 보헤님 지시 (2026-11-21). 「천장 없애라」 뒤에 「천장에 달리는 것이 있다면 실내에서 천장을 구현해야 한다」로 정정했다 |

### 9.2 구현 계획

1. **모드 2개**: 「도면 모드」(현재 화면, 스캔 도면 겹침)와 「실사 모드」를 전환한다. 도면 모드는 검수에 필요해서 남긴다.
2. **재질 (PBR)**: 바닥은 도면 표기대로 포세린타일 600 × 600에 줄눈을 넣는다. 벽 타일, 인조대리석, 거울 반사, 유리 투과, 도기 광택, 금속을 구분한다. 좌상단 마감 표를 300dpi로 읽어 반영한다.
3. **팔레트 (호텔 화장실 느낌, 작성자 제안)**: 따뜻한 베이지·그레이지 대형 타일, 짙은 우드 또는 차콜 칸막이, 무광 블랙 또는 브러시드 골드 금속, 거울 뒤와 선반 아래 간접 조명, 전구색 약 3000K. 화면을 보고 조정한다.
4. **빛**: 천장을 닫는다. 손글씨 「조명」 위치에 광원을 놓는다. 창으로 자연광이 들어온다. 부드러운 그림자, 접촉 음영(AO), 환경 반사, 톤 매핑을 넣는다. 조도 계산은 하지 않는다.
5. **형상**: 변기, 세면기, 수전을 곡면이 있는 형상으로 다시 만든다.
6. **고품질 렌더 버튼**: 현재 시점을 경로 추적(path tracing)으로 다듬은 정지 화면을 만든다. 라이브러리는 구현 전에 공식 문서로 확인한다.
7. **상식 보완 품목** (모두 출처 「가정」): 세면대 상판과 수전, 천장과 조명 기구, 칸막이 다리와 하부 틈, 문 손잡이와 잠금, 휴지걸이, 물비누, 핸드드라이어, 휴지통, 위생용품 수거함, 환기구, 창틀, 남서 실 중앙 배수구.
8. **이동**: 화살표 키 4개로 화면을 이동한다. `Shift` 를 함께 누르면 빠르게 이동한다. 화면 구석에 이동 버튼을 넣는다.
9. **검수**: 독립 검수는 도면 근거 품목만 대조한다. 추가 품목은 목록으로 따로 보고한다.

### 9.3 한계

- 브라우저 실시간 렌더는 오프라인 렌더보다 간접광 품질이 낮다. 고품질 렌더 버튼의 정지 화면으로 보완한다.
- 색과 제품은 도면에 없다. 작성자가 정한다.

### 9.5 고품질 렌더

- 「고품질 렌더」 는 켜고 끄는 스위치다. 기본은 꺼짐이다(보헤님 지시, 2026-11-21). 실사 모드의 도구 막대에 있다.
- 켜져 있으면 실사 모드의 아이소·눈높이 뷰에서 화면이 멈추고 1.5초 뒤에 현재 시점을 경로 추적으로 다듬기 시작한다.
- 시점이나 화면 구성을 바꾸면 그 렌더를 끝낸다. 실시간 화면으로 돌아간다. 멈추면 새 화면으로 처음부터 다시 만든다.
- 쉬는 경우: 평면 뷰, 품목을 선택한 동안(선택 강조와 정보 패널을 본다), 원본 도면을 보는 동안, 마우스로 시점을 움직이는 동안.
- 끄는 방법: 스위치 버튼, 진행 표시줄의 「끄기」, 렌더 중의 `Esc`. 끈 뒤에는 다시 켤 때까지 시작하지 않는다.
- 표본을 다 모으면 멈춘다. 오류가 나면 스위치를 스스로 끈다. 같은 오류를 되풀이하지 않게 한다.
- URL에 `hq=1` 을 붙이면 켠 채로 시작한다.
- 표본이 16개 모일 때까지 화면을 바꾸지 않는다(보헤님 결정 A, 2026-11-21). 그동안 실시간 실사 화면이 남아 있다. 표시줄에 「고품질 렌더 계산 중 · 표본 n / 16 · N초 · 16개 모이면 화면 전환」이 나온다. 표본이 적은 화면은 점투성이라서 보여 주지 않는다.
- 표시줄의 다른 글자: 「고품질 렌더 준비 중…」, 「고품질 렌더 셰이더 준비 중 · N초 (첫 실행은 몇 분 소요)」, 「고품질 렌더 완료(또는 진행 중) · 표본 a / b · N초」, 「고품질 렌더 중단 · 스위치 꺼짐: (오류)」.
- 브라우저가 소프트웨어 렌더링이면 스위치가 켜져 있는 동안 표시줄 자리에 한 줄을 더 보인다: 「브라우저의 그래픽 가속 꺼짐 · 고품질 렌더가 매우 느림 (Chrome 설정 → 시스템 → 그래픽 가속 사용)」. 고품질 렌더는 막지 않는다. 판별은 WebGL의 `UNMASKED_RENDERER_WEBGL` 문자열에 `swiftshader`, `llvmpipe`, `software`, `basic render` 가 있는지로 한다(`src/scene/softwareGl.ts`). 확장이 없으면 안내하지 않는다. 뷰어는 이미 고성능 GPU를 요청한다(`@react-three/fiber` 의 기본값 `powerPreference: 'high-performance'`).
- 스피너가 떠 있는 동안(5절 10번)에는 시작하지 않는다.
- 화면에 내놓을 때 노이즈 제거 필터를 거친다(보헤님 결정 B, 2026-11-21). 구현은 `src/scene/PathTracer.tsx` 의 `DENOISE` 다.
  - 점이 없는 실시간 화면을 길잡이로 쓴다. 길잡이에서 색이 비슷한 화소끼리만 섞는다.
  - 섞는 값은 「경로 추적 값 ÷ 길잡이 값」이다. 섞은 뒤에 길잡이 값을 곱한다. 타일 줄눈과 나뭇결은 길잡이에서 온다.
  - 섞는 반경은 표본 16개에서 32화소다. 표본 수의 제곱근에 반비례해서 줄어든다(표본 64개에서 16화소, 표본 400개에서 6.4화소).
  - 반경을 정한 근거(2026-11-21, 표본 16개 화면): 8은 벽에 잔 얼룩이 남는다. 16과 24는 구름 모양의 큰 얼룩이 남는다. 32에서 사라진다. 48은 창 옆 벽의 음영까지 지운다.
  - 밝은 점 상한(`clamp`)과 길잡이 색 차이(`guideSigma`)는 바꿔도 얼룩이 줄지 않았다. 처음 값 그대로다.
  - 표본을 32개까지 기다리는 방법은 쓰지 않는다. 반경이 같으면 표본 18개 화면과 32개 화면의 얼룩 차이가 작았다(나누기 전의 필터, 반경 16 이하로 비교했다).
  - 가로로 한 번, 세로로 한 번 나눠서 섞는다. 한 번에 섞으면 탭이 (2 × 반경 + 1)² 개다. 반경 16에서 그리기 1번이 이 PC에서 0.7초였다. 나눈 뒤에는 반경 32에서 0.06초다.
  - 길잡이 화면을 그릴 때는 거울 반사면을 켠다. 경로 추적 중에는 반사면을 숨기고 거울 상자의 재질이 직접 반사한다. 길잡이에 반사면이 없으면 거울 안쪽이 단색이라서 필터가 거울 속 모습을 뭉갠다. 반사면은 `guide-only`, 거울 상자는 `trace-only` 라는 이름의 그룹에 넣는다. 경로 추적기는 숨긴 물체를 건너뛴다.
  - 라이브러리의 `DenoiseMaterial` 은 쓰지 않는다. 점이 심한 화면에서는 효과가 없었다(표본 4개 화면으로 확인).
  - 확인하지 못한 것: 최종 값(반경 32, 가로·세로 분리)으로 표본 17개 이상을 모은 화면, 아이소 뷰의 고품질 렌더. 최종 값은 눈높이 뷰의 표본 16개 화면으로만 확인했다. 이 PC에서 표본 1개가 약 45초다.
  - 고품질 렌더를 켰다가 끄면 거울 반사면이 다시 보인다(2026-11-21, 켠 적 없는 화면과 비교해서 확인).
- 라이브러리는 `three-gpu-pathtracer` 0.0.28의 `WebGLPathTracer` 다. 이 클래스는 지원 중단이 예고됐다. 대체품 `WebGPUPathTracer` 는 WebGPU가 필요하다.
- 품질 값은 일반 사양 PC를 기준으로 잡았다(보헤님 지시): 표본 400, 화면 긴 변 1,920px 이하 전체 해상도, 반사 5회.
- 0.0.28의 큐브 환경맵 변환기는 `three` 0.187에서 실패한다(없어진 셰이더 조각 `cube_uv_reflection_fragment` 를 부른다). 경로 추적 중에만 하늘빛 그라데이션 환경으로 바꾼다. `three` 버전은 내리지 않았다.
- 타일 1장을 그린 뒤 GPU가 끝냈는지 확인하고 다음 타일을 그린다. 확인 없이 쌓으면 내장 그래픽에서 WebGL 컨텍스트가 사라진다. 타일 수는 16 × 16에서 시작해서 속도에 맞춰 줄인다.
- 컨텍스트가 사라지면 오류로 표시한다. 완료로 표시하지 않는다.
- 실측(Intel HD Graphics 4000 내장 그래픽, 화면 1,110 × 928px): 첫 셰이더 준비 약 130초(브라우저가 셰이더를 기억한 뒤에는 몇 초), 표본 1개 약 45초다. 표본 400을 끝까지 돌리지는 않았다. 이 PC에서는 약 5시간으로 추정한다.
- 같은 PC에서 자동 시작, 취소, 다시 시작을 시험했다. 취소 뒤 약 5초 안에 새 렌더가 시작했다. 렌더 중에 주 스레드가 멈춘 시간은 최대 0.97초였다. 조작은 막히지 않는다.
- 경로 추적기는 렌더러마다 1개만 만들어 다시 쓴다. 시작과 취소가 잦아도 GPU 메모리가 새지 않게 한다.
- 화면 PNG 저장은 아직 없다(2차 범위).

| 강조색 | `#5ab4ff` | `--accent` |
| 강조색 위의 글자 | `#000000` | `--on-accent` |

- 강조색은 참고 화면의 값 `#76b9ed` 에서 채도만 올린 값이다. 보헤님이 화면을 보고 「탁하다」고 해서 같은 색상(207°)의 후보 3개를 비교한 뒤에 골랐다(2026-11-22). `#0081fa` 는 넣었다가 되돌렸다. 강조색 위의 검정 글자는 대비 9.41 : 1이다.
- 참고 화면에 없어서 작성자가 정한 색(보통 버튼, 호버 단계, 출처 배지 3종의 어두운 판, 도면 주기 상자, 안내 상자, 반투명 색, 조작법 창 뒤의 막)도 같은 `:root` 에 변수로 있다.

### 10.2 규칙

- 선으로 나누지 않는다. 면의 밝기 차이로 구역을 나눈다.
- 강조색은 켜진 것과 고른 것에 쓴다: 선택된 탭, 실사/도면, 뷰, 고품질 렌더. 선택된 탭은 처음에 한 단계 밝은 면이었다. 눈에 띄지 않아서 강조색 면으로 바꿨다(보헤님 결정, 2026-11-22).
- 버튼은 바탕과 글자색을 한 쌍으로 정한다. 글자색을 물려받지 않는다. 물려받게 두면 놓이는 자리에 따라 바탕과 글자가 같은 색이 된다(원본 도면 창의 버튼 글자가 보이지 않던 버그의 원인이다).
- 레이어, 상식 보완 품목, 바닥 도면은 눈 아이콘 토글이다(`src/ui/EyeToggle.tsx`). 보이는 눈은 강조색이 아니라 흰색이다. 레이어는 대부분 켜져 있어서 강조색으로 하면 파란 아이콘이 세로로 늘어선다. `input[type=checkbox]` 를 남기고 화면에서만 숨겼다. 키보드와 화면 낭독기의 동작은 체크박스와 같다.
- 아이콘은 Lucide다(`lucide-react`, 보헤님 지정). 쓰는 아이콘만 이름으로 가져온다.
- 글꼴은 `'Segoe UI Variable', 'Segoe UI', 'Malgun Gothic', system-ui, sans-serif` 다. 한글은 맑은 고딕으로 그려진다.
- 반투명 색에 `color-mix()` 를 쓰지 않는다. 모르는 브라우저에서는 그 선언이 통째로 사라진다. rgba 값을 변수로 둔다.

### 10.2.1 글자 위계

크기만이 아니라 굵기와 색으로 단계를 나눈다(보헤님 결정, 2026-11-22). 11px보다 작은 글자는 쓰지 않는다.

| 단계 | 대상 | 크기 | 굵기 | 색 |
|---|---|---|---|---|
| 1 | 탭, 3D 화면 위의 버튼, 툴팁, 진행 막대 | 13px | 보통 | `--text` |
| 2 | 정보 카드의 제목(품목 이름, 도면명), 조작법 창의 제목 | 14px | 굵게 | `--text` |
| 3 | 카드 제목(표시 모드, 레이어 등), 탭 줄의 건물 이름 | 12px | 600 | `--text-sub` |
| 4 | 본문(토글 이름, 치수 표, 값 출처 설명, 실사/도면 버튼) | 12px | 보통 | `--text` |
| 5 | 보조(값 표시, 설명 글, 상태 표시줄) | 12px | 보통 | `--text-sub` |
| 6 | 배지 | 11px | 보통 | 배지색 |

좌우 패널의 한글은 낱말 단위로 줄을 바꾼다(`word-break: keep-all`).

### 10.3 테마를 따르지 않는 곳

| 자리 | 처리 | 까닭 |
|---|---|---|
| 실사 모드의 3D 바탕 | 전과 같다 | 거울 속 창밖 색과 묶여 있다(`RealStage.tsx`). 어두운 화면 안에서 본 뒤에 보헤님이 정한다 |

| 도면 모드의 3D 바탕 | `#272727` 로 바꿨다 | 색 값이 `Viewport.tsx` 에 한 번 더 적혀 있다. three.js는 CSS 변수를 읽지 못한다. `--bg-main` 을 바꾸면 같이 바꾼다 |
