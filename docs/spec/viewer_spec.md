# 뷰어 명세

2026-11-21 보헤님이 승인한 제안의 확정본이다.

## 1. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 3D 방식 | C안: 도면 치수로 직접 모델링하고 스캔 도면을 바닥에 깐다 | 원본이 스캔본이라 벡터와 텍스트를 추출할 수 없다. 바닥 도면이 모델 오차를 눈으로 드러낸다 |
| 조명 | 주목적이 아니다. 손글씨 「조명」 위치 마커만 넣는다 | 보헤님 답변 「아니다」 |
| 진행 순서 | 연구동 3층을 파일럿으로 먼저 만든다. 확인 후 나머지 7개를 만든다 | 외곽이 가장 작다 |
| 검수 | 탭을 만들 때마다 독립 검증 에이전트가 실제 도면과 대조한다 | 보헤님 지시. 작성자가 스스로 승인하지 않는다 |

## 2. 스택

- Vite + TypeScript + React
- three.js + @react-three/fiber + @react-three/drei
- 상태 관리 라이브러리는 쓰지 않는다. React 상태로 충분하다.
- 실행 중에 PDF를 읽지 않는다. `scripts/prep_plans.py` 로 8장을 기울기 보정 이미지로 1회 변환한다.
- 라이브러리 버전은 설치 시 최신을 받는다. 구현 전에 공식 문서로 API를 확인한다.

## 3. 좌표 규칙

- 단위는 mm다. 장면 단위는 m다(`Viewport.tsx` 의 `M = 0.001`).
- 평면 x는 동쪽(도면 오른쪽), y는 남쪽(도면 아래쪽), z는 바닥에서의 높이다.
- three.js 좌표는 X = x, Z = y, Y = z다.
- 탭마다 원점은 도면 치수선의 시작점이다. `Calibration` 이 300dpi 이미지 픽셀과 mm를 잇는다.

## 4. 값 출처 3종

모든 치수에 출처를 붙인다. 정보 패널이 배지로 표시한다.

| 값 | 코드 | 뜻 |
|---|---|---|
| 도면 표기 | `drawn` | 도면에 숫자로 적힌 치수 |
| 축척 환산 | `scaled` | 도면의 선 위치를 축척으로 환산한 값 |
| 가정 | `assumed` | 도면에 없어서 가정한 값. 대부분 높이다 |

평면도는 바닥 위치만 준다. 높이는 천장고(CH), 칸막이 높이처럼 도면에 적힌 값만 확정이다.

## 5. 기능

### 1차 범위

1. 탭 8개. 강의동 3개와 연구동 5개를 그룹으로 나눈다. 이름은 도면 우하단 도면명을 따른다.
2. 3D 모델: 벽, 칸막이, 문(도면에 그려진 열림 상태), 변기, 세면기, 수채기, 거울, 선반.
3. 바닥 도면 깔기와 불투명도 슬라이더.
4. 뷰 전환: 평면(직교) / 아이소 / 눈높이.
5. 절단 높이 슬라이더. 지정 높이 위를 그리지 않는다.
6. 조명 표시 레이어: 손글씨 「조명」 위치를 천장면 마커로 표시한다.
7. 레이어 켜기/끄기: 벽·창, 칸막이, 문, 위생기구, 거울·선반·부속, 조명 표시, 치수, 바닥 도면.
8. 클릭 정보 패널: 품목명, 도면 주기, 치수와 출처, 판독 메모.
9. 원본 도면 보기: 해당 페이지 이미지를 2D로 띄운다.

### 2차 범위 (미착수)

- 두 점 거리 측정
- 조명 위치에 실제 광원을 놓고 밝기 분포 보기
- 탭 2개 나란히 비교
- 화면 PNG 저장

## 6. 화면 배치

```
+------------------------------------------------------------------+
|강의동 [2F 여][3F 남][4F 여]  연구동 [1F][2F][3F 여][4F 남][5F 여]|
+--------------+------------------------------------+--------------+
| 레이어       |                                    | 정보 패널    |
| 바닥 도면    |            3D 뷰포트               | 품목·치수    |
| 불투명도     |                                    | 도면 주기    |
| 절단 높이    | [평면][아이소][눈높이][맞춤]       | 원본 도면    |
+--------------+------------------------------------+--------------+
| 도면명 | 축척 1/50(A3) | 커서 좌표 X,Y (mm) | 조작 안내          |
+------------------------------------------------------------------+
```

## 7. 마우스와 키보드

| 입력 | 아이소·눈높이 뷰 | 평면 뷰 |
|---|---|---|
| 왼쪽 드래그 | 회전 | 이동 |
| 오른쪽 드래그 | 이동 | 이동 |
| 휠 | 커서 위치 기준 확대·축소 | 같다 |
| 호버 | 품목 색 강조 + 이름 툴팁 | 같다 |
| 클릭 | 품목 선택, 정보 패널에 표시 | 같다 |
| 품목 더블클릭 | 그 지점으로 주시점 이동 | 같다 |
| 빈 바닥 더블클릭 | 전체 맞춤 | 같다 |

키보드: `1`~`8` 탭 전환, `F` 전체 맞춤, `Esc` 선택 해제와 원본 도면 닫기.

## 9. 실사 모드 (2026-11-21 추가, 미착수)

보헤님이 파일럿을 본 뒤 추가한 요구다. 다음 세션에서 연구동 3층 탭에 구현한다.

### 9.1 확정된 요구

| 항목 | 결정 | 근거 |
|---|---|---|
| 품질 목표 | 실사. 셰이더를 넣는다. 「top 건축사무소에서 만든 퀄리티 정도」 | 보헤님 지시 |
| 색상 | 호텔 화장실 느낌 | 보헤님 지시 |
| 상식 보완 | 도면에 없어도 상식적으로 있어야 하는 것은 넣는다 | 보헤님 지시 |
| 높이 | 실제 높이 자료는 없다. 상식적인 값으로 정한다. 다시 묻지 않는다 | 보헤님 답변 |
| X 표시 | 물이 빠지는 방향(바닥 구배)이다. 샤프트 표시가 아니다 | 보헤님 답변 |
| 남서 실 배수구 | X 표시 실의 중앙에 배수구를 넣는다 | 작성자 추정을 보헤님이 확인 |
| 위생기구 형상 | 외부 3D 모델을 받지 않고 직접 만든다. 제조사 제품과 똑같지는 않다 | 작성자 추정을 보헤님이 확인 |
| 화면 이동 | 마우스 오른쪽 드래그 이동은 동작한다(보헤님 확인). 키보드 화살표 이동을 추가한다 | 보헤님 요청 |
| 나머지 7개 탭 | 지시가 있을 때까지 착수하지 않는다 | 보헤님 지시 「착수하지 마라」 |

### 9.2 구현 계획

1. **모드 2개**: 「도면 모드」(현재 화면, 스캔 도면 겹침)와 「실사 모드」를 전환한다. 도면 모드는 검수에 필요해서 남긴다.
2. **재질 (PBR)**: 바닥은 도면 표기대로 포세린타일 600 × 600에 줄눈을 넣는다. 벽 타일, 인조대리석, 거울 반사, 유리 투과, 도기 광택, 금속을 구분한다. 좌상단 마감 표를 300dpi로 읽어 반영한다.
3. **팔레트 (호텔 화장실 느낌, 작성자 제안)**: 따뜻한 베이지·그레이지 대형 타일, 짙은 우드 또는 차콜 칸막이, 무광 블랙 또는 브러시드 골드 금속, 거울 뒤와 선반 아래 간접 조명, 전구색 약 3000K. 화면을 보고 조정한다.
4. **빛**: 천장을 닫는다. 손글씨 「조명」 위치에 광원을 놓는다. 창으로 자연광이 들어온다. 부드러운 그림자, 접촉 음영(AO), 환경 반사, 톤 매핑을 넣는다. 조도 계산은 하지 않는다.
5. **형상**: 변기, 세면기, 수전을 곡면이 있는 형상으로 다시 만든다.
6. **고품질 렌더 버튼**: 현재 시점을 경로 추적(path tracing)으로 다듬은 정지 화면을 만든다. 라이브러리는 구현 전에 공식 문서로 확인한다.
7. **상식 보완 품목** (모두 출처 「가정」): 세면대 상판과 수전, 천장과 조명 기구, 칸막이 다리와 하부 틈, 문 손잡이와 잠금, 휴지걸이, 물비누, 핸드드라이어, 휴지통, 위생용품 수거함, 환기구, 창틀, 남서 실 중앙 배수구.
8. **이동**: 화살표 키 4개로 화면을 이동한다. `Shift` 를 함께 누르면 빠르게 이동한다. 화면 구석에 이동 버튼을 넣는다.
9. **검수**: 독립 검수는 도면 근거 품목만 대조한다. 추가 품목은 목록으로 따로 보고한다.

### 9.3 한계

- 브라우저 실시간 렌더는 오프라인 렌더보다 간접광 품질이 낮다. 고품질 렌더 버튼의 정지 화면으로 보완한다.
- 색과 제품은 도면에 없다. 작성자가 정한다.
