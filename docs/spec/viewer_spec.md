# 뷰어 명세

2026-11-21 보헤님이 승인한 제안의 확정본이다.

## 1. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 3D 방식 | C안: 도면 치수로 직접 모델링하고 스캔 도면을 바닥에 깐다 | 원본이 스캔본이라 벡터와 텍스트를 추출할 수 없다. 바닥 도면이 모델 오차를 눈으로 드러낸다 |
| 조명 | 주목적이 아니다. 손글씨 「조명」 위치 마커만 넣는다 | 보헤님 답변 「아니다」 |
| 진행 순서 | 연구동 3층을 파일럿으로 먼저 만든다. 확인 후 나머지 7개를 만든다 | 외곽이 가장 작다 |
| 검수 | 탭을 만들 때마다 독립 검증 에이전트가 실제 도면과 대조한다 | 보헤님 지시. 작성자가 스스로 승인하지 않는다 |

## 2. 스택

- Vite + TypeScript + React
- three.js + @react-three/fiber + @react-three/drei
- 상태 관리 라이브러리는 쓰지 않는다. React 상태로 충분하다.
- 실행 중에 PDF를 읽지 않는다. `scripts/prep_plans.py` 로 8장을 기울기 보정 이미지로 1회 변환한다.
- 라이브러리 버전은 설치 시 최신을 받는다. 구현 전에 공식 문서로 API를 확인한다.

## 3. 좌표 규칙

- 단위는 mm다. 장면 단위는 m다(`Viewport.tsx` 의 `M = 0.001`).
- 평면 x는 동쪽(도면 오른쪽), y는 남쪽(도면 아래쪽), z는 바닥에서의 높이다.
- three.js 좌표는 X = x, Z = y, Y = z다.
- 탭마다 원점은 도면 치수선의 시작점이다. `Calibration` 이 300dpi 이미지 픽셀과 mm를 잇는다.

## 4. 값 출처 3종

모든 치수에 출처를 붙인다. 정보 패널이 배지로 표시한다.

| 값 | 코드 | 뜻 |
|---|---|---|
| 도면 표기 | `drawn` | 도면에 숫자로 적힌 치수 |
| 축척 환산 | `scaled` | 도면의 선 위치를 축척으로 환산한 값 |
| 가정 | `assumed` | 도면에 없어서 가정한 값. 대부분 높이다 |

평면도는 바닥 위치만 준다. 높이는 천장고(CH), 칸막이 높이처럼 도면에 적힌 값만 확정이다.

## 5. 기능

### 1차 범위

1. 탭 8개. 강의동 3개와 연구동 5개를 그룹으로 나눈다. 이름은 도면 우하단 도면명을 따른다.
2. 3D 모델: 벽, 칸막이, 문(도면에 그려진 열림 상태), 변기, 세면기, 수채기, 거울, 선반.
3. 바닥 도면 깔기와 불투명도 슬라이더.
4. 뷰 전환: 평면(직교) / 아이소 / 눈높이.
5. 절단 높이 슬라이더. 지정 높이 위를 그리지 않는다.
6. 조명 표시 레이어: 손글씨 「조명」 위치를 천장면 마커로 표시한다.
7. 레이어 켜기/끄기: 벽·창, 칸막이, 문, 위생기구, 거울·선반·부속, 조명 표시, 치수, 바닥 도면.
8. 클릭 정보 패널: 품목명, 도면 주기, 치수와 출처. 판독 메모(`Item.remark`)는 화면에 표시하지 않는다(보헤님 지시, 2026-11-21). 데이터 파일에 기록으로만 둔다.
9. 원본 도면 보기: 해당 페이지 이미지를 2D로 띄운다.

### 2차 범위 (미착수)

- 두 점 거리 측정
- 조명 위치에 실제 광원을 놓고 밝기 분포 보기
- 탭 2개 나란히 비교
- 화면 PNG 저장

## 6. 화면 배치

```
+------------------------------------------------------------------+
|강의동 [2F 여][3F 남][4F 여]  연구동 [1F][2F][3F 여][4F 남][5F 여]|
+--------------+------------------------------------+--------------+
| 레이어       |                                    | 정보 패널    |
| 바닥 도면    |            3D 뷰포트               | 품목·치수    |
| 불투명도     |                                    | 도면 주기    |
| 절단 높이    | [평면][아이소][눈높이][맞춤]       | 원본 도면    |
+--------------+------------------------------------+--------------+
| 도면명 | 축척 1/50(A3) | 커서 좌표 X,Y (mm) | 조작 안내          |
+------------------------------------------------------------------+
```

## 7. 마우스와 키보드

| 입력 | 아이소·눈높이 뷰 | 평면 뷰 |
|---|---|---|
| 왼쪽 드래그 | 회전 | 이동 |
| 오른쪽 드래그 | 이동 | 이동 |
| 휠 | 커서 위치 기준 확대·축소 | 같다 |
| 호버 | 품목 색 강조 + 이름 툴팁 | 같다 |
| 클릭 | 품목 선택, 정보 패널에 표시 | 같다 |
| 품목 더블클릭 | 그 지점으로 주시점 이동 | 같다 |
| 빈 바닥 더블클릭 | 전체 맞춤 | 같다 |

키보드: `1`~`8` 탭 전환, `F` 전체 맞춤, `Esc` 선택 해제와 원본 도면 닫기(고품질 렌더 중이면 그 스위치를 끈다), 화살표 키 화면 이동(`Shift` 를 함께 누르면 빠르게 이동한다).

## 9. 실사 모드 (2026-11-21 추가, 연구동 3층 탭에 구현)

보헤님이 파일럿을 본 뒤 추가한 요구다. 연구동 3층 탭에 구현했다. 구현 내용은 9.4절에 있다.

### 9.1 확정된 요구

| 항목 | 결정 | 근거 |
|---|---|---|
| 품질 목표 | 실사. 셰이더를 넣는다. 「top 건축사무소에서 만든 퀄리티 정도」 | 보헤님 지시 |
| 색상 | 호텔 화장실 느낌 | 보헤님 지시 |
| 상식 보완 | 도면에 없어도 상식적으로 있어야 하는 것은 넣는다 | 보헤님 지시 |
| 높이 | 실제 높이 자료는 없다. 상식적인 값으로 정한다. 다시 묻지 않는다 | 보헤님 답변 |
| X 표시 | 물이 빠지는 방향(바닥 구배)이다. 샤프트 표시가 아니다 | 보헤님 답변 |
| 남서 실 배수구 | X 표시 실의 중앙에 배수구를 넣는다 | 작성자 추정을 보헤님이 확인 |
| 위생기구 형상 | 외부 3D 모델을 받지 않고 직접 만든다. 제조사 제품과 똑같지는 않다 | 작성자 추정을 보헤님이 확인 |
| 화면 이동 | 마우스 오른쪽 드래그 이동은 동작한다(보헤님 확인). 키보드 화살표 이동을 추가한다 | 보헤님 요청 |
| 고품질 렌더 | 켜고 끄는 스위치다. 기본은 꺼짐이다 | 보헤님 지시 (2026-11-21. 처음에 켜짐으로 정했다가 화면을 본 뒤 꺼짐으로 바꿨다) |
| 천장 | 실내에서 볼 때만 그린다. 위에서 내려다볼 때는 그리지 않는다 | 보헤님 지시 (2026-11-21). 「천장 없애라」 뒤에 「천장에 달리는 것이 있다면 실내에서 천장을 구현해야 한다」로 정정했다 |
| 품질 기준 PC | 품질 값은 보헤님 PC(내장 그래픽)가 아니라 일반 사양 PC를 기준으로 잡는다 | 보헤님 지시 (2026-11-21) |
| 나머지 7개 탭 | 지시가 있을 때까지 착수하지 않는다 | 보헤님 지시 「착수하지 마라」 |

### 9.2 구현 계획

1. **모드 2개**: 「도면 모드」(현재 화면, 스캔 도면 겹침)와 「실사 모드」를 전환한다. 도면 모드는 검수에 필요해서 남긴다.
2. **재질 (PBR)**: 바닥은 도면 표기대로 포세린타일 600 × 600에 줄눈을 넣는다. 벽 타일, 인조대리석, 거울 반사, 유리 투과, 도기 광택, 금속을 구분한다. 좌상단 마감 표를 300dpi로 읽어 반영한다.
3. **팔레트 (호텔 화장실 느낌, 작성자 제안)**: 따뜻한 베이지·그레이지 대형 타일, 짙은 우드 또는 차콜 칸막이, 무광 블랙 또는 브러시드 골드 금속, 거울 뒤와 선반 아래 간접 조명, 전구색 약 3000K. 화면을 보고 조정한다.
4. **빛**: 천장을 닫는다. 손글씨 「조명」 위치에 광원을 놓는다. 창으로 자연광이 들어온다. 부드러운 그림자, 접촉 음영(AO), 환경 반사, 톤 매핑을 넣는다. 조도 계산은 하지 않는다.
5. **형상**: 변기, 세면기, 수전을 곡면이 있는 형상으로 다시 만든다.
6. **고품질 렌더 버튼**: 현재 시점을 경로 추적(path tracing)으로 다듬은 정지 화면을 만든다. 라이브러리는 구현 전에 공식 문서로 확인한다.
7. **상식 보완 품목** (모두 출처 「가정」): 세면대 상판과 수전, 천장과 조명 기구, 칸막이 다리와 하부 틈, 문 손잡이와 잠금, 휴지걸이, 물비누, 핸드드라이어, 휴지통, 위생용품 수거함, 환기구, 창틀, 남서 실 중앙 배수구.
8. **이동**: 화살표 키 4개로 화면을 이동한다. `Shift` 를 함께 누르면 빠르게 이동한다. 화면 구석에 이동 버튼을 넣는다.
9. **검수**: 독립 검수는 도면 근거 품목만 대조한다. 추가 품목은 목록으로 따로 보고한다.

### 9.3 한계

- 브라우저 실시간 렌더는 오프라인 렌더보다 간접광 품질이 낮다. 고품질 렌더 버튼의 정지 화면으로 보완한다.
- 색과 제품은 도면에 없다. 작성자가 정한다.

### 9.4 구현 내용 (2026-11-21)

| 항목 | 구현 |
|---|---|
| 모드 전환 | 왼쪽 패널의 「표시 모드」 [실사][도면]. 처음 화면은 실사 모드다(보헤님 지시, 2026-11-21). 전환해도 시점은 유지된다. 모델이 없는 탭은 도면 모드만 쓴다 |
| URL 인자 | `mode=plan` 은 도면 모드로 시작한다. `added=0` 은 상식 보완 품목을 두 모드 모두에서 끈다. `added=1` 은 두 모드 모두에서 켠다. `hq=1` 은 고품질 렌더 스위치를 켠 채로 시작한다 |
| 품목 구분 | 도면 근거 품목과 상식 보완 품목(`Item.added`)을 데이터 파일로 나눴다. 왼쪽 패널의 「상식 보완 품목」으로 켜고 끈다. 켜짐 상태는 모드마다 따로 기억한다. 기본값은 도면 모드 꺼짐, 실사 모드 켜짐이다. 도면 모드는 스캔 도면과 대조하는 화면이라서 도면에 없는 품목을 숨긴다. 정보 패널이 품목 수를 따로 센다 |
| 마감 레이어 | 바닥, 화장실 벽 타일, 수채기실 벽 타일, 천장은 `finish` 레이어다. 실사 모드에서만 그린다. 도면 모드에서는 스캔 도면이 바닥이다 |
| 재질 | 외부 이미지를 받지 않는다. 타일, 목재, 인조대리석, 화강석, 천장 패널 질감을 캔버스에 그려서 만든다. 타일 한 칸은 실제 크기다 |
| 팔레트 | 벽은 아이보리 베이지 포세린타일, 바닥은 그레이지 포세린타일, 칸막이는 짙은 월넛, 금속은 브러시드 골드, 도기는 흰색이다. 작성자 제안이다 |
| 빛 | 손글씨 「조명」 3곳과 상식 보완 매입등 7개, 간접 조명 2개에 광원을 놓았다. 색은 전구색이다. 북측 창으로 자연광이 들어온다. 그림자, 접촉 음영(N8AO), 환경 반사, ACES 톤 매핑을 쓴다 |
| 거울 | 거울 1장마다 장면을 한 번 더 그려서 비춘다(three.js `Reflector`). 거울끼리는 서로 지난 화면을 쓴다 |
| 형상 | 양변기, 세면기, 수전, 수채기를 곡면 도형(`lathe`, `rbox`, `tube`, `plate`)으로 다시 만들었다. 평면 크기와 중심은 검수받은 값 그대로다 |
| 천장 | 절단 높이가 천장고와 같을 때와 눈높이 뷰에서, 카메라가 천장보다 낮으면 그린다. 카메라가 천장보다 높으면 그리지 않는다. 위에서 실내를 들여다볼 수 있다. 천장면의 조명 기구와 환기구는 두 경우 모두 그린다 |
| 화면 다시 그리기 | 실사 모드는 화면이 바뀔 때만 다시 그린다 |
| 이동 | 화살표 키와 화면 오른쪽 아래의 이동 버튼. 1번에 250mm, `Shift` 를 누르면 1,000mm다 |

### 9.5 고품질 렌더

- 「고품질 렌더」 는 켜고 끄는 스위치다. 기본은 꺼짐이다(보헤님 지시, 2026-11-21). 실사 모드의 도구 막대에 있다.
- 켜져 있으면 실사 모드의 아이소·눈높이 뷰에서 화면이 멈추고 1.5초 뒤에 현재 시점을 경로 추적으로 다듬기 시작한다.
- 시점이나 화면 구성을 바꾸면 그 렌더를 끝낸다. 실시간 화면으로 돌아간다. 멈추면 새 화면으로 처음부터 다시 만든다.
- 쉬는 경우: 평면 뷰, 품목을 선택한 동안(선택 강조와 정보 패널을 본다), 원본 도면을 보는 동안, 마우스로 시점을 움직이는 동안.
- 끄는 방법: 스위치 버튼, 진행 표시줄의 「끄기」, 렌더 중의 `Esc`. 끈 뒤에는 다시 켤 때까지 시작하지 않는다.
- 표본을 다 모으면 멈춘다. 오류가 나면 스위치를 스스로 끈다. 같은 오류를 되풀이하지 않게 한다.
- URL에 `hq=1` 을 붙이면 켠 채로 시작한다.
- 표본이 16개 모일 때까지 화면을 바꾸지 않는다(보헤님 결정 A, 2026-11-21). 그동안 실시간 실사 화면이 남아 있다. 표시줄에 「계산 중 · 표본 n / 16」이 나온다. 표본이 적은 화면은 점투성이라서 보여 주지 않는다.
- 화면에 내놓을 때 노이즈 제거 필터를 거친다(보헤님 결정 B, 2026-11-21). 구현은 `src/scene/PathTracer.tsx` 의 `DENOISE` 다.
  - 점이 없는 실시간 화면을 길잡이로 쓴다. 길잡이에서 색이 비슷한 화소끼리만 섞는다.
  - 섞는 값은 「경로 추적 값 ÷ 길잡이 값」이다. 섞은 뒤에 길잡이 값을 곱한다. 타일 줄눈과 나뭇결은 길잡이에서 온다.
  - 섞는 반경은 표본 16개에서 32화소다. 표본 수의 제곱근에 반비례해서 줄어든다(표본 64개에서 16화소, 표본 400개에서 6.4화소).
  - 반경을 정한 근거(2026-11-21, 표본 16개 화면): 8은 벽에 잔 얼룩이 남는다. 16과 24는 구름 모양의 큰 얼룩이 남는다. 32에서 사라진다. 48은 창 옆 벽의 음영까지 지운다.
  - 밝은 점 상한(`clamp`)과 길잡이 색 차이(`guideSigma`)는 바꿔도 얼룩이 줄지 않았다. 처음 값 그대로다.
  - 표본을 32개까지 기다리는 방법은 쓰지 않는다. 반경이 같으면 표본 18개 화면과 32개 화면의 얼룩 차이가 작았다(나누기 전의 필터, 반경 16 이하로 비교했다).
  - 가로로 한 번, 세로로 한 번 나눠서 섞는다. 한 번에 섞으면 탭이 (2 × 반경 + 1)² 개다. 반경 16에서 그리기 1번이 이 PC에서 0.7초였다. 나눈 뒤에는 반경 32에서 0.06초다.
  - 길잡이 화면을 그릴 때는 거울 반사면을 켠다. 경로 추적 중에는 반사면을 숨기고 거울 상자의 재질이 직접 반사한다. 길잡이에 반사면이 없으면 거울 안쪽이 단색이라서 필터가 거울 속 모습을 뭉갠다. 반사면은 `guide-only`, 거울 상자는 `trace-only` 라는 이름의 그룹에 넣는다. 경로 추적기는 숨긴 물체를 건너뛴다.
  - 라이브러리의 `DenoiseMaterial` 은 쓰지 않는다. 점이 심한 화면에서는 효과가 없었다(표본 4개 화면으로 확인).
  - 확인하지 못한 것: 최종 값(반경 32, 가로·세로 분리)으로 표본 17개 이상을 모은 화면, 아이소 뷰의 고품질 렌더. 최종 값은 눈높이 뷰의 표본 16개 화면으로만 확인했다. 이 PC에서 표본 1개가 약 45초다.
  - 고품질 렌더를 켰다가 끄면 거울 반사면이 다시 보인다(2026-11-21, 켠 적 없는 화면과 비교해서 확인).
- 라이브러리는 `three-gpu-pathtracer` 0.0.28의 `WebGLPathTracer` 다. 이 클래스는 지원 중단이 예고됐다. 대체품 `WebGPUPathTracer` 는 WebGPU가 필요하다.
- 품질 값은 일반 사양 PC를 기준으로 잡았다(보헤님 지시): 표본 400, 화면 긴 변 1,920px 이하 전체 해상도, 반사 5회.
- 0.0.28의 큐브 환경맵 변환기는 `three` 0.187에서 실패한다(없어진 셰이더 조각 `cube_uv_reflection_fragment` 를 부른다). 경로 추적 중에만 하늘빛 그라데이션 환경으로 바꾼다. `three` 버전은 내리지 않았다.
- 타일 1장을 그린 뒤 GPU가 끝냈는지 확인하고 다음 타일을 그린다. 확인 없이 쌓으면 내장 그래픽에서 WebGL 컨텍스트가 사라진다. 타일 수는 16 × 16에서 시작해서 속도에 맞춰 줄인다.
- 컨텍스트가 사라지면 오류로 표시한다. 완료로 표시하지 않는다.
- 실측(Intel HD Graphics 4000 내장 그래픽, 화면 1,110 × 928px): 첫 셰이더 준비 약 130초(브라우저가 셰이더를 기억한 뒤에는 몇 초), 표본 1개 약 45초다. 표본 400을 끝까지 돌리지는 않았다. 이 PC에서는 약 5시간으로 추정한다.
- 같은 PC에서 자동 시작, 취소, 다시 시작을 시험했다. 취소 뒤 약 5초 안에 새 렌더가 시작했다. 렌더 중에 주 스레드가 멈춘 시간은 최대 0.97초였다. 조작은 막히지 않는다.
- 경로 추적기는 렌더러마다 1개만 만들어 다시 쓴다. 시작과 취소가 잦아도 GPU 메모리가 새지 않게 한다.
- 화면 PNG 저장은 아직 없다(2차 범위).
