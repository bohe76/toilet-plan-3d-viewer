## 2. 보헤님이 정한 것 (2026-11-22)

- 절단 높이의 기본값은 탭마다의 최대값이다. 실사와 도면 두 모드, 8개 탭 모두 같다.
- 눈높이 뷰는 제자리에서 고개를 돌리는 조작으로 바꾼다. 위아래 각도를 사람이 고개를 들고 내려보는 정도로 제한한다.
- 화면의 글자는 「~다.」 문장을 쓰지 않는다. 명사로 끝낸다(「값이다」 → 「값」).
- 탭을 바꿀 때 로딩 스피너를 먼저 보이고, 화면이 구성되면 지운다.
- 테마는 Windows 11 시계 앱의 어두운 테마를 따른다. 범위는 B(색과 모양)다.
- 원본 도면 썸네일의 구석에 「크게 보기」 표시를 항상 둔다. 호버 때는 판과 테두리가 강조색이 되고, 그림이 살짝 커지고, 커서가 돋보기가 된다.
- 배포해도 된다.
- 구현은 보헤님이 시작하라고 할 때 시작한다. 제안에 대한 「좋다」는 시작 지시가 아니다.

## 3. 뷰어 조작 5건

### 3.1 절단 높이의 기본값을 탭의 최대값으로

- 지금: `DEFAULT_CUT = 1200` (`src/App.tsx:30`). 처음 값(`:43`)과 탭 전환 때의 값(`:149`)이 1,200이다.
- 바꿀 것: 처음 값과 탭 전환 때의 값을 그 탭의 천장고(슬라이더의 최대값)로 한다. 모든 뷰에 같다.
- 방법: `cutHeight` 의 기본을 `Infinity` 로 둔다. `effectiveCut = Math.min(cutHeight, ceiling)` (`:82`)이 탭마다 최대값이 된다. URL의 `cut=` 인자는 그대로 쓴다.
- 최대값: 2,350(강의동 3F), 2,450(강의동 2F, 연구동 2F·4F·5F), 2,500(연구동 1F), 2,550(연구동 3F), 2,800(강의동 4F).
- 알고 있는 결과: 평면 뷰에서 문 위의 벽이 문 개구를 덮는다. 아이소 뷰에서 앞쪽 벽이 실내 일부를 가린다. 슬라이더를 내리면 지금처럼 보인다. 보헤님에게 알렸고 그대로 가기로 했다.
- 딸린 일: 검수자에게 주는 평면 캡처는 1,200 기본값에 기대고 있다. 명령에 `cut=1200` 을 붙인다(6절).

### 3.2 눈높이 뷰: 제자리에서 고개 돌리기

지금은 눈높이 뷰도 아이소 뷰와 같은 `OrbitControls` 로 몇 미터 앞의 점을 공전한다(`src/scene/Viewport.tsx:450`). 카메라가 벽을 뚫고 올라가고 위를 볼 수 없다.

| 조작 | 바꿀 동작 (눈높이 뷰에서만) |
|---|---|
| 왼쪽 드래그 | 제자리에서 둘러본다. 좌우는 360°다 |
| 위아래 각도 | 수평에서 위 60°, 아래 60°까지 |
| 드래그 방향 | 화면을 잡고 끄는 방식. 오른쪽으로 끌면 그림이 오른쪽으로 따라온다 |
| 드래그 양 | 커서 밑의 그림이 커서를 따라오는 정도. 화면 높이만큼 끌면 세로 시야각(45°)만큼 돈다 |
| 눈높이 | 그 탭의 `model.eye.from` 높이(1,600)로 고정 |
| 휠 | 앞뒤로 걷는다. 한 칸이 화살표 키 한 번(`PAN_STEP`)이다. 확대는 끈다 |
| 오른쪽 드래그, 가운데 버튼 | 끈다 |
| 화살표 키, ▲▼◀▶ | 지금처럼 걷는다 |
| 더블클릭 | 찍은 지점으로 걸어간다. 높이와 보는 방향은 유지한다. 바닥(높이 약 0.1m 이하)을 찍으면 그 점 위에 선다. 높은 곳을 찍으면 그 점의 1m 앞에서 멈춘다 |
| F 키, 「맞춤」 | 지금처럼 처음 위치로 돌아간다 |
| 벽 통과 | 막지 않는다 |

평면 뷰와 아이소 뷰의 조작은 바꾸지 않는다.

먼저 검토할 구현 안:

- `OrbitControls` 를 그대로 쓴다. 눈높이 뷰에서만 주시점을 카메라의 1cm 앞에 둔다.
- `enableZoom=false`, `enablePan=false`, `minPolarAngle=30°`, `maxPolarAngle=150°`. 극각은 「카메라 − 주시점」 벡터의 각이라서 위 60°가 150°, 아래 60°가 30°다.
- `rotateSpeed` 의 크기는 45 / 360이다. 부호는 화면을 잡고 끄는 방식이 되게 실험으로 정한다. 추론으로 정하지 않는다.
- 카메라 놓기 effect(`:386`)의 눈높이 분기는 `target = from + normalize(to − from) × 0.01` 이 된다.
- 화살표 이동 effect(`:427`)는 카메라와 주시점을 같이 옮기므로 그대로 쓴다.
- 휠은 캔버스의 `wheel` 리스너(눈높이 뷰에서만, `passive: false`)로 같은 이동을 한다.
- 이 안이 요구를 채우지 못하면 작은 전용 조작기를 쓴다.

깨지면 안 되는 것:

- `CameraRig` 의 세 effect(카메라 놓기, 더블클릭 초점, 화살표 이동)는 `controls.current` 를 쓴다. 눈높이 뷰에서 조작기가 없어지면 카메라가 놓이지 않는다.
- 실사 모드는 `frameloop='demand'` 다. 카메라를 직접 움직이면 `invalidate()` 를 부른다.
- 고품질 렌더는 조작기의 `onChange`(→ `onInterrupt`), `onStart` / `onEnd`(→ `onDrag`)에 기대고 있다. 눈높이 뷰의 드래그, 휠, 더블클릭 이동에서도 시점이 바뀌면 `onInterrupt` 가 불려야 한다.
- 품목의 더블클릭은 `onFocus`(주시점 이동)이고 바닥판(`Floor`)의 더블클릭은 `onFit`(맞춤)이다(`:288`). 눈높이 뷰에서는 둘 다 「그 지점으로 걸어가기」가 된다. 다른 뷰는 그대로 둔다.

상태 표시줄의 조작 안내(`src/App.tsx:399`)에 눈높이 뷰용 글자를 둔다:
`왼쪽 드래그: 둘러보기 · 휠: 앞뒤 이동 · 화살표: 이동 (Shift 빠르게) · 클릭: 선택 · 더블클릭: 그 지점으로 이동 · 1~8: 탭 · F: 맞춤`

### 3.4 화면 전환 로딩 스피너

- 언제: 탭을 바꿀 때, 처음 접속할 때, 실사 ↔ 도면을 바꿀 때.
- 순서: 누르면 스피너와 누른 탭의 강조를 먼저 그린다. 그 다음 프레임에 장면을 바꾼다. 새 장면의 첫 화면이 그려진 뒤에 스피너를 지운다. 도면 모드에서 바닥 도면이 보이는 설정이면 스캔 도면 이미지가 뜬 뒤에 지운다.
- 모양: 3D 화면 영역(`.stage`)만 덮는 막과 가운데의 도는 원. 탭 줄과 좌우 패널은 가리지 않는다. 색은 테마의 값을 쓴다(4절).
- 회전은 CSS `transform` 애니메이션으로 한다. 장면을 만드는 동안 메인 스레드가 멈춰도 돌게 하려는 것이다.

주의할 것:

- `requestAnimationFrame` 한 번은 그리기 전에 불린다. 스피너가 그려진 뒤에 장면을 바꾸려면 두 번 겹쳐 쓴다.
- 지금 탭을 다시 누르거나 그 번호 키를 누르면 스피너를 띄우지 않는다. 띄우면 지울 계기가 없어서 남는다.
- 이미지 로드가 실패해도 남지 않게 시간 제한(예: 30초)을 둔다.
- 스피너가 떠 있는 동안에는 고품질 렌더를 시작하지 않는다(`canTrace` 조건, `App.tsx:133`).
- 실사 모드는 `frameloop='demand'` 다. 「첫 화면이 그려졌다」는 프레임이 실제로 돌았는지로 안다(예: 장면이 바뀐 뒤 `useFrame` 이 두 번째로 불릴 때).
- 전환 도중에 다른 탭을 또 누르면 마지막에 누른 탭이 이긴다.
- 확인하지 못한 것: 셰이더를 준비하는 동안 이 PC의 GPU(Intel HD 4000)에서 CSS 회전이 계속 도는지. 멈춰 보일 수 있다. 구현 뒤에 확인해서 보헤님에게 알린다.

### 3.5 그래픽 가속이 꺼진 브라우저 안내

- 뷰어는 이미 고성능 GPU를 요청한다. `@react-three/fiber` 9.8.2의 기본값이 `powerPreference: 'high-performance'` 다. 이 부분은 넣을 것이 없다. (4차 세션에서 보헤님에게 「요청하지 않는다」고 잘못 답했다가 바로잡았다.)
- 넣을 것: WebGL의 `WEBGL_debug_renderer_info` 확장으로 `UNMASKED_RENDERER_WEBGL` 을 읽는다. `swiftshader`, `llvmpipe`, `software`, `basic render` 가 들어 있으면(대소문자 무시) 소프트웨어 렌더링으로 본다. 확장이 없으면 안내하지 않는다.
- 소프트웨어 렌더링이고 고품질 렌더 스위치가 켜져 있으면 진행 막대 자리에 한 줄을 보인다: `브라우저의 그래픽 가속 꺼짐 · 고품질 렌더가 매우 느림 (Chrome 설정 → 시스템 → 그래픽 가속 사용)`. 고품질 렌더는 막지 않는다.
- 판별 함수는 문자열을 받는 순수 함수로 떼어 둔다. 값으로 시험한다.
- 이 가지는 지금의 헤드리스 Chrome에서 나오지 않는다(GPU가 Intel HD 4000으로 잡힌다). Chrome을 소프트웨어 GL로 한 번 띄워서 확인하거나, 확인하지 못했다고 보고한다.

보헤님에게 답한 내용(참고): Chrome 설정 → 시스템 → 「가능한 경우 그래픽 가속 사용」이 꺼져 있으면 CPU로 계산한다. `chrome://gpu` 에서 「WebGL: Hardware accelerated」인지 본다. GPU가 둘인 PC는 Windows 설정 → 디스플레이 → 그래픽 → Chrome → 「고성능」으로 고른다. GPU가 Intel HD 4000 하나인 PC는 이 설정으로 빨라지지 않는다.

| 선택된 항목 | `#2d2d2d` | `--bg-selected` |
| 떠 있는 판 | `#2c2c2c` | `--bg-float` |
| 글자 | `#ffffff` | `--text` |
| 보조 글자 | `#d0d0d0` | `--text-sub` |
| 꺼진 글자 | `#7d7d7d` | `--text-off` |
| 강조색 | `#76b9ed` | `--accent` |
| 강조색 위의 글자 | `#000000` | `--on-accent` |
| 꺼진 스위치의 테두리 | `#cfcfcf` | `--switch-off` |

색은 `styles.css` 의 `:root` 변수 한 곳에 둔다. 밝은 테마와의 전환 스위치는 넣지 않는다.

참고 화면에서 읽은 특징:

- 선으로 나누지 않는다. 면의 밝기 차이(3단계)로 구역을 나눈다.
- 강조색은 켜진 것에만 쓴다. 선택된 메뉴는 강조색이 아니라 한 단계 밝은 면이다.
- 모서리가 둥글다(카드 약 8px). 꺼진 항목은 글자를 흐리게 한다.

### 4.2 자리마다의 적용

| 자리 | 지금 | 바꿀 것 |
|---|---|---|
| 탭 줄, 상태 표시줄 | 흰색 + 회색 선 | `--bg-base`, 선 없음 |
| 좌우 패널 | 흰색 | `--bg-main` 바탕에 구획마다 `--bg-card` 카드(모서리 8px). 구획은 표시 모드, 레이어, 바닥 도면 불투명도, 절단 높이, 정보, 원본 도면이다 |
| 탭 | 테두리가 있는 버튼, 선택은 파란 버튼 | 테두리 없는 글자 버튼. 선택된 탭은 `--bg-selected` 면 + 흰 글자. 건물 이름(강의동, 연구동)은 보조 글자 |
| 켜진 버튼 (실사/도면, 뷰, 고품질 렌더) | 파란 버튼 | `--accent` + `--on-accent` |
| 레이어, 상식 보완 품목, 바닥 도면 | 체크박스 | 참고 화면의 스위치. 켜지면 `--accent`, 꺼지면 `--switch-off` 테두리. 못 쓰는 항목은 글자를 `--text-off` 로 |
| 슬라이더 | 브라우저 기본색 | `accent-color: var(--accent)` |
| 출처 배지 3종 | 밝은 초록·파랑·주황 판 | 같은 색상의 어두운 판(어두운 바탕 + 밝은 글자) |
| 도면 주기 상자, 안내 상자 | 밝은 회색, 연노랑 | 어두운 판. 주기의 왼쪽 띠는 `--accent` |
| 3D 화면 위의 버튼 묶음(뷰, 이동), 툴팁, 진행 막대 | 흰 버튼, 남색 막대 | `--bg-float` 판 |
| 로딩 스피너 | 없음 | 막은 `--bg-main` 의 반투명, 원은 `--accent` |
| 원본 도면 창 | 어두운 막 + 흰 버튼 | 테마의 버튼. 아래 4.3의 버그를 같이 고친다 |
| 글꼴 | 맑은 고딕, Segoe UI | `'Segoe UI Variable', 'Segoe UI', 'Malgun Gothic', system-ui, sans-serif` 를 검토한다. 한글은 맑은 고딕으로 그려진다 |

스위치는 `input[type=checkbox]` 를 그대로 두고 CSS로 모양만 바꾼다. 키보드와 화면 낭독기의 동작을 유지한다.

### 4.3 원본 도면 창의 버튼 글자 (버그)

- 증상: 원본 도면 창의 위쪽 버튼 3개(「−」, 「+」, 「닫기 (Esc)」)의 글자가 보이지 않는다. 보헤님이 찾았다.
- 원인: 버튼의 공통 규칙이 「바탕은 흰색, 글자색은 물려받는다」다(`styles.css:4`). 위쪽 막대의 글자색이 흰색이다(`styles.css:66`). 흰 바탕에 흰 글자가 된다. 진행 막대에는 이것을 막는 규칙이 있다(`styles.css:47`). 원본 도면 창에는 없다.
- 처리: 테마에서 버튼의 바탕과 글자색을 한 쌍으로 정한다. 글자색을 물려받지 않게 한다. 다른 곳에 같은 문제가 없는지 화면 전체를 확인한다.

### 4.4 원본 도면 썸네일

지금은 누를 수 있다는 표시가 없다. 마우스를 올려도 보이는 변화가 없다(`styles.css:59`).

- 평소: 썸네일을 테마의 카드 안에 넣는다. 그림의 오른쪽 아래 구석에 작은 판을 항상 둔다. 판에는 확대 아이콘(⤢)과 「크게 보기」 글자가 있다. 판의 색은 `--bg-float`(약간 투명)다.
- 마우스를 올리면 4가지가 함께 바뀐다(보헤님 최종 결정, 2026-11-22: 「이거대로 하자」). 0.15초에 걸쳐 바뀐다.
  1. 판이 `--accent` + `--on-accent`(검정 글자)로 바뀐다.
  2. 그림의 테두리가 `--accent` 2px가 된다.
  3. 그림이 1.03배로 살짝 커진다(카드 밖으로 넘치지 않는다).
  4. 커서가 돋보기(+)가 된다(`zoom-in`).
- 키보드 초점(`:focus-visible`)에도 같은 테두리를 보인다.
- 뺀 것: 「검정 막 + 가운데 글자」. 구석의 판이 같은 말을 한다.
- 지나온 논의: 보헤님이 한때 「그림 자체의 호버 효과는 없어도 된다」, 「살짝 커지는 것은 오케이」라고 했다. 그 뒤에 위 4가지를 모두 넣기로 정했다.

### 9.2 계획에 없이 더한 것

- **조작법 창.** 처음 접속하면 뜬다. 「다시 보지 않기」를 로컬 스토리지에 저장한다. 도구 묶음의 「조작법」 버튼으로 다시 연다. 버튼의 글자 앞에 도움말 아이콘을 두었다. 내용은 스펙 5절 12번에 있다.
- **`W` `A` `S` `D` 로도 이동한다.** 화살표 키와 같다. 글자가 아니라 키 자리로 판정해서 한글 입력 상태에서도 듣는다. `F`(맞춤)도 같은 방식으로 바꿨다.
- **처음 보이는 탭을 첫 탭(강의동 2F 여)으로 바꿨다.** 전에는 파일럿인 연구동 3F였다. `sheet=` 인자가 있으면 그 탭이다.
- **도면명에서 「(변경후)」를 지웠다.** 화면에 나오는 8개 도면명이다. 데이터 파일의 주석과 문서의 도면명은 PDF에 적힌 이름 그대로 두었다.
- **끌고 나서 뗀 것은 클릭으로 치지 않는다**(조율자가 화면에서 찾았다). 끈 거리가 2px보다 크면 선택을 바꾸지 않는다. 없으면 눈높이 뷰에서 둘러볼 때마다 품목이 선택되고, 고품질 렌더가 다시 시작하지 않는다.
- **휠 입력을 100px 단위로 모아서 걷는다**(작성자와 검토자가 지적했다). 없으면 트랙패드에서 한 번 쓸 때 수 m를 걷는다. 마우스 휠 한 칸은 250mm 그대로다.
- **치수 라벨을 3D 화면 영역에서 자른다**(조율자가 화면에서 찾았다). 전에는 라벨이 패널과 상태 표시줄 위로 나오고 페이지에 세로 스크롤바가 생겼다. 라벨만 담는 층을 따로 두었다. 툴팁은 자르지 않는다.
- **좌우 패널의 한글은 낱말 단위로 줄을 바꾼다**(작성자 판단). 본문을 12px로 줄이자 낱말 가운데서 줄이 바뀌는 곳이 생겼다.
- **3D 화면 위의 버튼의 초점 링을 흰 링과 검은 링 두 겹으로 그린다**(검토자가 지적했다). 흰 도면 위에서도 보이게 하려는 것이다.

### 9.3 계획대로 하지 않고 남긴 것

- **실사 ↔ 도면 버튼의 강조는 장면이 바뀔 때 함께 바뀐다.** 누르는 즉시 강조되는 것은 탭뿐이다. 계획 3.4가 요구한 것은 탭의 강조다. 스피너는 즉시 뜬다.
- **지금 탭을 다시 누르면 절단 높이와 선택이 초기화된다.** 스피너는 뜨지 않는다. 그 탭의 번호 키는 아무것도 하지 않는다. 전과 같은 동작이다.

- 셰이더를 준비하는 동안(이 PC에서 7 ~ 14초) 스피너의 회전이 계속 도는지. 그동안은 캡처 도구도 멈춘다.
- 그래픽 가속 꺼짐 안내의 실제 화면. 이 PC의 Chrome은 Intel HD 4000으로 잡힌다. 판별 함수는 문자열로 시험했다.
- 화면에 띄우지 못한 글자: 「3D 모델 작성 전 · …」(모델 없는 탭이 지금 없다), 고품질 렌더 오류 문구, 컨텍스트 손실 문구.
- 저장소가 막힌 브라우저에서 조작법 창이 매번 뜨는지. 코드의 예외 처리만 확인했다.
- 오래된 브라우저(`color-mix()` 를 모르는 판, `::backdrop` 에서 변수를 읽지 못하는 판)의 화면.
