## 3. 확정된 결정

- 3D 방식은 C안이다(치수 기반 모델 + 스캔 도면 깔기).
- 품질 목표는 실사다. 색상은 호텔 화장실 느낌이다.
- 도면에 없어도 상식적으로 있어야 하는 것은 넣는다. 높이는 상식값으로 정한다. 다시 묻지 않는다.
- X 표시는 물이 빠지는 방향(바닥 구배)이다.
- 위생기구 형상은 직접 만든다. 외부 3D 모델을 받지 않는다.
- 탭을 만들 때마다 독립 검증 에이전트가 실제 도면과 대조한다. 검수자에게 작성자의 결론을 주지 않는다.
- 도면의 선 위치와 표기 치수가 다르면 표기 치수를 따른다. (작성자 판단)
- 아이소·평면 뷰의 기본 절단 높이는 1,200이다. 눈높이 뷰는 절단하지 않는다.
- TypeScript는 6.x를 쓴다. `typescript-eslint` 가 7.0을 지원하지 않는다.
- 품질 값(표본 수, 해상도)은 보헤님 PC(내장 그래픽)가 아니라 일반 사양 PC를 기준으로 잡는다. 보헤님 PC에서는 멈추지 않게만 한다. (보헤님 지시, 2026-11-21)
- 고품질 렌더는 켜고 끄는 스위치다. 기본은 꺼짐이다. (보헤님 지시, 2026-11-21)
- 천장은 실내에서 볼 때만 그린다. 카메라가 천장보다 높으면 그리지 않는다. (보헤님 지시, 2026-11-21)
- 표시 모드는 [실사][도면] 순서다. 처음 화면은 실사 모드다. (보헤님 지시, 2026-11-21)
- 고품질 렌더는 표본이 일정 수 모인 뒤에 화면을 바꾸고(A), 노이즈 제거 필터를 건다(B). (보헤님 결정, 2026-11-21)
- 정보 패널에 판독 메모를 표시하지 않는다. 메모는 데이터 파일의 `remark` 에 기록으로만 둔다. (보헤님 지시, 2026-11-21)
- 7개 탭은 병렬로 구현한다. 작성 에이전트와 검증 에이전트를 탭마다 따로 둔다. (보헤님 승인, 2026-11-22: 「제안대로 해라」)

## 4. 작성자와 조율자가 정한 것 (보헤님 확인 대상)

### 3차 세션까지

- 팔레트: 아이보리 베이지 벽 타일, 그레이지 바닥 타일, 짙은 월넛 칸막이, 브러시드 골드 금속, 흰색 도기.
- 상식 보완 품목의 종류, 위치, 크기. 목록은 탭마다 `src/data/<탭>_added.ts` 에 있다.
- 세면대 상판 아래 전면을 칸막이 패널로 막았다(연구동 3F. 도면은 서쪽 500 패널 1개만 판독된다).
- 칸막이 하부 틈 150, 세면대 상판 윗면 820, 세면기 테두리 832.
- 도면 모드는 상식 보완 품목을 기본으로 숨긴다.
- 노이즈 제거 필터를 직접 만들었다. 반경은 32다. 근거는 스펙 9.5절에 있다.
- 고품질 렌더 스위치를 켜면 화면이 멈추고 1.5초 뒤에 자동으로 시작한다. 품목을 선택한 동안과 평면 뷰에서는 쉰다.
- 벽 마감은 벽 안쪽 면에 3mm 면으로 그렸다(도면 표기 T10). 10mm로 그리면 벽에 붙은 거울을 덮는다.

### 4차 세션 (7개 탭)

규칙의 전문은 [tab_author_brief.md](../guides/tab_author_brief.md) 5절의 15 ~ 23번에 있다. 여기에는 화면에 영향이 큰 것만 적는다.

- **문은 도면에 그려진 상태(열린 상태)로 둔다.** 문짝의 폭은 그려진 문짝 선의 길이다. 문틀은 그려진 블록 그대로다. 닫았을 때 문짝이 문틀과 겹치는 값은 `remark` 에만 적는다. 문틀을 깎거나 문짝을 줄이지 않는다.
- **「"A" 단면상세도」를 형상에 반영했다.** 강의동 3장은 출입구의 틀 머리 높이다(천장고 − 70 부근). 연구동 1F와 2F는 창 위 커텐박스의 단면이다. 커텐박스는 천장 끝에서 150 올라간 THK1.6 갈바 판이다. 판과 창 사이는 천장이 없는 홈이다. 창 상단은 천장고 + 150이다. 연구동 3F, 4F, 5F에는 상세도가 없다.
- **구역마다 천장고가 다르면 천장을 나눈다.** 연구동 2F의 남 「+」 구역은 표기 CH 2,800을 따랐다. `ceilingHeight` 는 본실의 값이다.
- **소변기 뒤 띠는 끊지 않는다.** 점묘가 소변기 뒤에서도 이어진다. 소변기의 뒤판이 띠 안에 묻히는 것은 허용했다.
- **코너 비드는 모서리가 실제로 있는 높이 구간에만 둔다.** 비드의 날개가 3mm 마감 면과 겹치는 것은 허용했다. 구조 벽과의 겹침은 0건이다.
- **손글씨 「조명」이 없는 형광펜에는 조명 품목을 만들지 않았다.** 사실만 기록했다(연구동 2F 남 「+」 구역).
- **거울이 벽에서 26 ~ 30 떨어져 그려진 곳은 벽 면에 붙였다.** `remark` 에 거리를 적었다.
- **출입문 문짝의 아래 끝은 재료분리대 윗면(노출 10)이다.**
- **연구동 1F의 창틀 자리(폭 41)의 벽면에는 마감을 넣지 않았다.** 창틀(상식 보완 품목)이 덮는 자리다. 도면 모드는 상식 보완 품목을 숨기므로 그때는 맨 벽면이 보인다. 실사 모드에서는 보이지 않는다.
- **커텐박스의 홈은 상식 보완 품목을 숨겨도 닫혀 있게 했다**(연구동 1F, 2F). 중앙 벽의 천장 위 부분을 벽 품목에 더했다. 그 두께는 가정이다.
- 장애인용 칸의 기구, 슬라이딩 도어, 소변기 칸막이, 커텐박스, 창틀은 공유 부품 `src/data/parts_extra.ts` 로 만들었다.

### 뷰어

- 고품질 렌더의 표본 400 완주는 확인하지 못했다. 이 PC(Intel HD Graphics 4000)에서 표본 1개가 약 45초다.

- 번들이 2.31MB다(gzip 0.73MB, 빌드 경고). 경로 추적 라이브러리를 지연 로딩하면 줄일 수 있다. 아직 하지 않았다.

- 칸 문짝의 경첩 모서리가 앞 칸막이와 6 × 6mm 겹친다. 공유 부품 `stallDoor` 의 형상이다. 전 탭이 같다. 화면에서 보이지 않는다.
- 3mm 벽 마감 면을 칸막이와 기구가 관통하는 곳이 여러 탭에 있다. 화면에서 보이지 않는다.

- 단면상세도의 홈 윗면 위 「150」 구간은 그리지 않았다. 가는 선의 뜻을 상세도로 정할 수 없다. 실내에서 보이지 않는 구간이다.
- 연구동 3F와 5F의 세면대 상판의 구분이 다르다. 3F는 세면기 앞의 가로선을 상판 앞 선으로 읽어서 상판이 도면 근거 품목이다. 5F는 같은 위치의 선이 「+」 구역까지 이어져서 바닥 타일 선으로 읽었다. 5F의 상판은 상식 보완 품목이다. 실사 모드의 모양은 같다. 도면 모드에서는 5F의 상판이 기본으로 숨는다.
- 닫힌 상태의 문은 볼 수 없다. 문을 여닫는 기능은 없다.

## 6. 환경 메모

### OMC 훅 시간 초과

- 증상: 도구 호출이 「PreToolUse hook error: [node]: the hook did not finish」로 거부된다.
- 원인: OMC 플러그인의 `PreToolUse` 훅(`pre-tool-enforcer.mjs`)이 모든 도구 호출 앞에서 node를 띄운다. CPU 부하가 100%일 때 제한 시간을 넘긴다.
- 조치(2026-11-21 1차 세션): 플러그인 캐시의 `hooks.json` 에서 `PreToolUse` 의 `timeout` 을 5에서 20으로 바꿨다. OMC를 업데이트하면 5로 돌아간다.
- 거부되면 같은 호출을 다시 보낸다. 호출을 한 번에 하나씩 보내면 덜 난다.
- `git commit` 은 훅 때문에 120초를 넘길 수 있다. 제한 시간을 300초로 준다.

### 화면 확인

- 개발 서버는 `pnpm dev --port 5183 --strictPort` 다. 뷰포트는 1600 × 1000으로 고정한다.
- MCP(chrome-devtools, chrome-devtools-headless, playwright)는 3차, 4차 세션에서 모두 연결 시간 초과였다. Chrome을 `--headless=new --remote-debugging-port=9333` 로 띄우고 `work/tools/cdp.mjs` 로 DevTools Protocol을 직접 부른다.
- 에이전트의 캡처에는 `hq=1` 을 붙이지 않는다. 고품질 렌더는 이 PC에서 표본 1개가 45초다.
- 고품질 렌더 중에 `src/` 파일을 저장하지 않는다. HMR이 렌더를 다시 시작해서 모은 표본을 버린다.
- 실사 모드의 첫 화면은 셰이더 준비 때문에 이 PC에서 13초쯤 걸린다.

| `bead_overlap.mjs <all.json>` | 코너 비드의 날개와 `wall` 레이어 상자의 겹침을 찾는다 |
| `leaf_threshold.mjs <all.json>` | 문짝과 재료분리대의 겹침을 찾는다 |

`work/` 를 지우면 이 도구도 없어진다. 다시 필요하면 새로 쓴다.

### 병렬 작업 방식 (4차 세션)

- 작성은 `executor`, 검수는 `verifier` (opus) 에이전트가 했다. 검수자는 차수마다 새로 띄웠다.
- 검수자에게는 빈 폴더 `work/verify/pN/vK/` 에 `model.json` 과 `top.png` 만 주었다. 측정값 문서, 검수 기록, 앞선 차수의 폴더, 작성자의 스크립트는 읽지 못하게 했다.
- 지침은 [tab_author_brief.md](../guides/tab_author_brief.md)와 [tab_verifier_brief.md](../guides/tab_verifier_brief.md)다.
- 에이전트가 끝나도 알림이 오지 않는 일이 잦았다. 15분마다 상태를 점검했다.
- 실행 중인 에이전트에게 보낸 메시지는 없어지지 않는다. 지금 하는 일이 끝난 뒤에 처리된다.
- 한 작성자의 파일이 깨진 동안에는 다른 에이전트의 캡처도 오류 화면이 된다. 작성자는 저장할 때마다 컴파일이 되게 한다.

### 그 밖

- 이 PC는 내장 그래픽(Intel HD Graphics 4000)이다. 다른 Claude 세션, Codex, `next dev`, Docker가 함께 돌 때 CPU 부하가 100%가 된다.
- 다른 프로젝트의 프로세스는 고아여도 끝내지 않는다. 보고만 한다. (보헤님 지시)
- 측정 스크립트용 파이썬 환경은 프로젝트 루트의 `.venv` 다(pymupdf, numpy, opencv). git에 넣지 않는다. 없으면 README의 명령으로 만든다.
- `work/` 는 git에 넣지 않는다. 검수 근거 이미지(`work/verify/`)도 그 안에 있다. 지우면 `prep_plans.py` 와 `measure_plan.py` 로 도면 이미지는 다시 만들 수 있다. 검수 근거 이미지는 다시 만들어야 한다.
- 줄 끝: 작업 폴더의 파일은 CRLF와 LF가 섞여 있다. git의 autocrlf가 커밋할 때 정리한다. 파일을 고칠 때는 그 파일의 줄 끝을 유지한다.
- 개발 서버와 헤드리스 Chrome은 세션 종료 때 내린다.

### 공개 배포 (GitHub Pages)

- 주소: <https://bohe76.github.io/toilet-plan-3d-viewer/> (공개 저장소 `bohe76/toilet-plan-3d-viewer`)
- 공개 저장소에는 빌드 결과물(`dist/` 의 내용과 `.nojekyll`)만 있다. 소스, 문서, PDF는 없다. 스캔 도면 이미지 8장(`plans/plan_N.jpg`)은 뷰어가 쓰기 때문에 들어 있다.
- **이 작업 저장소의 `main` 을 공개 저장소에 푸시하지 않는다.** 기록에 PDF와 문서가 있다. 이 작업 저장소에는 원격을 달지 않는다.
- 다시 배포하는 순서:
  1. `pnpm build` 를 실행한다.
  2. 프로젝트 밖의 빈 폴더에 `gh repo clone bohe76/toilet-plan-3d-viewer` 로 공개 저장소를 받는다.
  3. 받은 폴더에서 `.git` 과 `.nojekyll` 을 뺀 파일을 지운다. `dist/` 의 내용을 복사한다.
  4. 작성자 메일이 GitHub noreply 주소인지 확인한다(`git config user.email`). 개인 메일이면 그 폴더에서만 noreply 주소로 바꾼다.
  5. 커밋하고 `git push` 한다. 1 ~ 2분 뒤에 주소에서 확인한다.
