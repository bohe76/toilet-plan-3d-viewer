## 3. 확정된 결정

- 3D 방식은 C안이다(치수 기반 모델 + 스캔 도면 깔기).
- 품질 목표는 실사다. 색상은 호텔 화장실 느낌이다.
- 도면에 없어도 상식적으로 있어야 하는 것은 넣는다. 높이는 상식값으로 정한다. 다시 묻지 않는다.
- X 표시는 물이 빠지는 방향(바닥 구배)이다.
- 위생기구 형상은 직접 만든다. 외부 3D 모델을 받지 않는다.
- 탭을 만들 때마다 독립 검증 에이전트가 실제 도면과 대조한다. 검수자에게 작성자의 결론을 주지 않는다.
- 도면의 선 위치와 표기 치수가 다르면 표기 치수를 따른다. (작성자 판단)
- 아이소·평면 뷰의 기본 절단 높이는 1,200이다. 눈높이 뷰는 절단하지 않는다.
- TypeScript는 6.x를 쓴다. `typescript-eslint` 가 7.0을 지원하지 않는다.
- 품질 값(표본 수, 해상도)은 보헤님 PC(내장 그래픽)가 아니라 일반 사양 PC를 기준으로 잡는다. 보헤님 PC에서는 멈추지 않게만 한다. (보헤님 지시, 2026-11-21)
- 고품질 렌더는 켜고 끄는 스위치다. 기본은 켜짐이다. (보헤님 지시, 2026-11-21)

## 4. 작성자가 정한 것 (보헤님 확인 대상)

- 팔레트: 아이보리 베이지 벽 타일, 그레이지 바닥 타일, 짙은 월넛 칸막이, 브러시드 골드 금속, 흰색 도기.
- 상식 보완 품목 36개의 종류, 위치, 크기. 목록은 `src/data/research_3f_added.ts` 에 있다.
- 세면대 상판 아래 전면을 칸막이 패널로 막았다(도면은 서쪽 500 패널 1개만 판독된다).
- 칸막이 하부 틈 150, 세면대 상판 윗면 820, 세면기 테두리 832.
- 표시 모드의 기본은 도면 모드다. 도면 모드는 상식 보완 품목을 기본으로 숨긴다.
- 고품질 렌더는 화면이 멈추고 1.5초 뒤에 자동으로 시작한다. 품목을 선택한 동안과 평면 뷰에서는 쉰다.
- 「타일 덧대기(적층) (THK 50)」는 수채기실 동측 벽의 주기로만 달았다. 형상에는 반영하지 않았다(적용 범위 판독 불가).
- 출입문 경첩 쪽의 재료분리대 동쪽(X 3,810 ~ 3,900)은 바닥 타일로 메웠다. 재료분리대의 점묘 해치는 문짝 선에서 끝난다. 가로선은 동측 벽까지 이어진다. 재료분리대가 벽까지 이어지는 것일 수도 있다.
- 벽 마감은 벽 안쪽 면에 3mm 면으로 그렸다(도면 표기 T10). 10mm로 그리면 벽에 붙은 거울을 덮는다.

## 5. 알려진 한계

- 고품질 렌더의 표본 400 완주는 확인하지 못했다. 이 PC(Intel HD Graphics 4000)에서 표본 1개가 약 45초다.
- `WebGLPathTracer` (three-gpu-pathtracer 0.0.28)는 지원 중단이 예고됐다. 대체품은 WebGPU가 필요하다.
- 경로 추적 중에는 환경을 하늘빛 그라데이션으로 바꾼다. 0.0.28의 큐브 환경맵 변환기가 three 0.187에서 실패하기 때문이다.
- 고품질 렌더 화면의 PNG 저장은 없다(2차 범위).
- 번들이 2.04MB다(빌드 경고). 경로 추적 라이브러리를 지연 로딩하면 줄일 수 있다. 아직 하지 않았다.
- 도면 모드에서 세면대 상판이 스캔 도면의 세면대 구역과 배수구 기호를 가린다. 상판이 도면 근거 품목이 됐기 때문이다. 「거울·선반·부속」 레이어를 끄면 보인다.

## 6. 환경 메모

### OMC 훅 시간 초과

- 증상: 도구 호출이 「PreToolUse hook error: [node]: the hook did not finish」로 거부된다.
- 원인: OMC 플러그인의 `PreToolUse` 훅(`pre-tool-enforcer.mjs`)이 모든 도구 호출 앞에서 node를 띄운다. CPU 부하가 100%일 때 제한 시간을 넘긴다.
- 조치(2026-11-21 1차 세션): 플러그인 캐시의 `hooks.json` 에서 `PreToolUse` 의 `timeout` 을 5에서 20으로 바꿨다. OMC를 업데이트하면 5로 돌아간다. `omc-patch-all` 등록은 보헤님이 처리한다.
- 2차 세션에서도 거부가 여러 번 났다. 거부되면 같은 호출을 다시 보낸다. 호출을 한 번에 하나씩 보내면 덜 난다.

### 화면 확인

- chrome-devtools-headless MCP로 확인한다. 뷰포트는 1600 × 1000으로 고정한다. 개발 서버는 `pnpm dev --port 5183 --strictPort` 다.
- 실사 모드를 캡처할 때는 URL에 `hq=0` 을 붙인다. 붙이지 않으면 고품질 렌더가 자동으로 시작한다.
- 실사 모드의 첫 화면은 셰이더 준비 때문에 이 PC에서 13초쯤 걸린다. 그 뒤는 1장에 25 ~ 43ms다.

### 그 밖

- 이 PC는 내장 그래픽(Intel HD Graphics 4000)이다. 다른 Claude 세션, Codex, `next dev`, Docker가 함께 돌 때 CPU 부하가 100%가 된다.
- 측정 스크립트용 파이썬 환경은 프로젝트 루트의 `.venv` 다(pymupdf, numpy, opencv). git에 넣지 않는다. 없으면 README의 명령으로 만든다.
- `work/` 는 git에 넣지 않는다. 검수 근거 이미지(`work/verify/p6/`)도 그 안에 있다. 지우면 `prep_plans.py` 와 `measure_plan.py` 로 도면 이미지는 다시 만들 수 있다. 검수 근거 이미지는 다시 만들어야 한다.
- 줄 끝: 작업 폴더의 파일은 CRLF와 LF가 섞여 있다. git의 autocrlf가 커밋할 때 정리한다. 파일을 고칠 때는 그 파일의 줄 끝을 유지한다.
- 개발 서버는 세션 종료 때 내린다. `pnpm dev` 로 다시 띄운다.
