# 탭 검수자 지침서

탭 1개의 모델 데이터를 도면과 대조하는 독립 검증 에이전트가 읽는다. 검수자는 작성자와 다른 에이전트다. 회차마다 새 에이전트가 맡는다.

## 1. 순서

1. 원본 도면을 직접 읽는다. `work/plans_300/plan_N.jpg`, `work/measure/pN/` 의 눈금자 타일과 `segments.json` 을 쓴다.
2. 축척과 원점을 스스로 구한다. 도면에 인쇄된 치수와 치수 보조선의 픽셀 위치로 구한다. 그 뒤에 데이터 파일의 보정값과 비교한다.
3. `work/verify/pN/model.json` 의 품목을 하나씩 도면과 대조한다. 이 파일은 데이터 파일의 도형을 최종 좌표(mm)로 풀어 쓴 것이다.
4. 도면의 주기와 기호를 하나씩 짚어 빠진 품목을 찾는다.
5. 평면 화면 `work/verify/pN/top.png` 에서 모델과 바닥 도면이 겹치는지 본다.
6. 3절의 형식으로 보고한다.

타일과 선분을 읽는 법, 선분 검출의 함정은 [measurement_workflow.md](measurement_workflow.md)에 있다.

## 2. 규칙

- **읽지 않는 것**: `docs/drawings/<탭>_measurements.md`, 다른 탭의 데이터 파일과 검수 기록. 작성자의 결론이 들어 있다. 같은 결론을 따라가게 된다.
- **믿지 않는 것**: 데이터 파일의 주석과 `remark`. 작성자의 주장이다. 도면과 대조할 대상이다.
- **대상**: 도면 근거 품목(`src/data/<탭>.ts`)이다. `added: true` 인 상식 보완 품목은 도면과 대조하지 않는다.
- **기준**: 위치와 치수의 차이 10mm다. 인쇄 치수와 선 위치가 다르면 인쇄 치수가 맞는 값이다.
- **고치지 않는다**: 프로젝트의 파일을 고치지 않는다. 확대본과 측정 스크립트는 `work/verify/pN/` 에 조율자가 정한 접두(예: `v1_`)로 둔다.
- **근거를 남긴다**: 불일치마다 픽셀 좌표나 타일 이름을 적는다. 검수자도 틀린다. 연구동 3층 2차 검수에서 검수자가 자기 오류 4건을 바로잡았다.
- 개발 서버와 Chrome을 띄우거나 끄지 않는다. git의 상태를 바꾸는 명령을 쓰지 않는다.
- 도구 호출이 「PreToolUse hook error」로 거부되면 같은 호출을 다시 보낸다.

## 3. 대조 항목과 보고 형식

| 항목 | 볼 것 |
|---|---|
| 축척·원점 | 치수선 분할을 전부 환산해서 인쇄 치수와 비교한다 |
| 벽 | 위치, 두께, 개구, 창, 기둥 |
| 칸막이 | 위치, 길이, 수 |
| 문 | 수, 경첩 위치, 열림 방향, 문짝 폭. 문짝 선의 양 끝을 타일에서 읽는다 |
| 위생기구 | 종류, 수, 중심, 방향, 평면 크기 |
| 부속 | 거울, 선반, 창대석, 재료분리대, 점형블럭, 표지판, 코너 비드, 가방걸이 |
| 손글씨 「조명」 | 수와 위치 |
| 마감 | 좌상단 마감 표의 행과 평면의 마감 주기가 `finish` 품목에 있는지 |
| 출처 표시 | `drawn` 값의 숫자를 도면에서 찾는다 |
| 도면 주기 | `note` 가 도면 글자와 같은지. 지시선이 가리키는 대상이 맞는지 |
| 치수선 | 도면의 치수선이 `dimLines` 에 전부 있는지. 위치가 같은지 |
| 누락·과잉 | 도면에 있는데 모델에 없는 것, 모델에 있는데 도면에 없는 것 |

보고는 아래 순서로 쓴다.

1. 종합 판정: PASS, 조건부 PASS, FAIL 중 하나. 높음·중간·낮음 등급의 건수.
2. 항목별 판정 표.
3. 불일치 목록: 번호, 등급, 대상 id, 도면의 값, 데이터의 값, 근거(픽셀 좌표나 타일).
4. 판정하지 못한 것과 그 이유.

등급의 뜻은 이렇다. 높음은 수·배치·방향이 틀린 것이다. 중간은 30mm를 넘는 차이나 빠진 품목이다. 낮음은 10 ~ 30mm의 차이나 글자의 차이다.
